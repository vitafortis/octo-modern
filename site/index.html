Features

Everything you do in OctoPrint, for every printer at once

One push connection per printer you're watching, fanned out to every browser. Printers nobody is looking at get a light status poll.

Live dashboard & temperatures

Job progress, time left and ETA, and a live chart per hotend, bed and chamber. Set targets or use OctoPrint's presets.

Webcam streams

MJPEG relayed through octo·modern, so cameras on a LAN address work anywhere. Fullscreen, several cameras, flip and rotation.

Files & uploads

Local storage and SD card, thumbnails, search and sort. Drag in G-code of hundreds of MB; it streams to OctoPrint, then prints if you like.

Print control that asks first

Print, pause, resume, restart and cancel. Cancelling, deleting, emergency stop and risky G-code always confirm, enforced by the server too.

Control & Terminal

Jog, home, fans, feed and flow, custom controls. Underneath, a live serial log with filters and search, and a G-code prompt with history and autocomplete; expand it to the whole tab.

Discover + Application Keys

Finds OctoPrint in Docker, Arcane, over mDNS or a subnet scan, and Klipper's Moonraker over mDNS. Approve octo·modern in OctoPrint; there's no key to copy.

Every printer in one place

Add any number of OctoPrint servers and Klipper printers (through Moonraker, with auto-detection). State and progress in a calm sidebar (admin pages behind one Settings entry), six tabs per printer, an overview card for each, and ⌘K to jump anywhere.

Roles, SSO & audit log

Admins, operators and viewers, per-printer access, any OIDC provider, and a log of every print, upload and G-code with who and where.

Status API for dashboards

Read-only tokens for Homepage, Glance, Uptime Kuma and Home Assistant, plus SVG badges. Polling never reaches OctoPrint.

Keys stay on the server

OctoPrint API keys are sealed with AES-256-GCM and never sent to a browser. Every request, stream and upload goes through octo·modern.

One small container

amd64 and arm64 images, an unprivileged user and a single /data volume. No Docker socket, no native modules.

Encrypted backup & restore

Printers, keys, users and SSO settings in one passphrase-sealed file that restores on a fresh install.

Print from your NAS

Browse G-code on a mounted share, SMB, SFTP or WebDAV with thumbnails, print time and filament, then send it to any printer and start the print.

G-code preview

See the toolpath in 3D or layer by layer, coloured by walls, infill and supports, for files on a printer or in the library. During a print it follows the nozzle live. 100 MB files load in about a second.

Camera wall & kiosk

Every webcam on one page with state, progress and temperatures on top. Kiosk mode for a wall tablet keeps the screen on, hides the cursor and rotates cameras; many cameras switch to snapshots.

Print history

Every print on every printer, even with no browser open: result, duration, filament, who started it and a snapshot of the finish. Stats as a tab of History, CSV export and print again.

Stats

Print hours per printer, outcomes over time, success rate, filament per material and spool, cost, most-printed files, failure reasons and utilisation, in your time zone, with a CSV.

AI failure detection

Your own Obico ML container watches each print. A smoothed failure score warns you with the annotated frame and can pause a print that has turned to spaghetti.

Notifications

Browser push, ntfy, Discord, Slack, Telegram, Pushover, Gotify, Matrix, email, Home Assistant or webhooks, with the webcam snapshot: started, milestones, paused (runout, M600), done, failed, cancelled, offline, still hot. Rules per printer, quiet hours, a delivery log.

Smart plug power

Shelly, Tasmota, Home Assistant or any HTTP switch: power on (and connect), see the watts, and turn off by itself once a print is done and the hotend has cooled. Asks twice before cutting a running print.

Print queue

One queue for every printer: jobs for a specific printer or any printer with the right tags, copies, drag to reorder. The next job starts once someone confirms the bed is clear.

Upload from your slicer

PrusaSlicer, OrcaSlicer and Cura see octo·modern as an OctoPrint server. Each upload key sends files to the queue, a NAS folder or one printer.

Spoolman & cost per print

Pick the active Spoolman spool per extruder, report each print's filament to Spoolman, get warned before a print the spool won't finish, and see what every print cost in filament and power.

Maintenance reminders

Nozzle, belts, rails, bed and e-steps on intervals of print hours, filament or days, counted from the print history, with overdue badges, notifications and a log of who did what.

Bed mesh

With the Bed Visualizer plugin: the mesh as a heatmap and a 3D surface, flatness and range, probe it from here, compare any two meshes and get a notification when the bed drifts.

Plugins & updates

For admins: OctoPrint's version and the newer one, one-click updates that wait out OctoPrint's restart, plugin updates, enable, disable and uninstall plugins, install from the plugin repository with a live log, restart OctoPrint. Never mid-print, and a notification when something new is out.

Level before every print

Bed leveling (heating the bed first, if you like) and your own G-code before each print, for all printers or per printer, skipped when the file already does it. The printer shows Preparing, with Cancel, until they finish.

An app, with push

Install it on your phone (an Install app button where the browser can) and it opens full screen like an app. Turn on browser push per device and get prints and printer alerts on your phone, only for the printers you can see. Needs HTTPS.

Android app

Your octo·modern in an app: live print progress in the notification shade with Pause and Cancel, a finished-print notice with the snapshot, a home-screen widget per printer and an optional fingerprint lock. No Google account or Firebase; install the APK from GitHub Releases.

Install

Running in a minute

octo·modern is one container with one volume. It needs nothing installed on your OctoPrint machines.

Start it with Docker Compose

Fetch the ready-made compose.yaml and start it:

shell
mkdir octo-modern && cd octo-modern
curl -fsSLO https://raw.githubusercontent.com/vitafortis/octo-modern/main/compose.yaml
docker compose up -d

Or write it yourself. This is all it needs:

compose.yaml
services:
  octo-modern:
    image: ghcr.io/vitafortis/octo-modern:latest
    container_name: octo-modern
    restart: unless-stopped
    ports:
      - "3040:3000"
    environment:
      TZ: Etc/UTC
    volumes:
      - octo-modern-data:/data
    extra_hosts:
      # reach an OctoPrint published on the Docker host itself
      - host.docker.internal:host-gateway

volumes:
  octo-modern-data:

Using Arcane? Add compose.yaml as a new project in Arcane and deploy it. Everything octo·modern stores lives in the octo-modern-data volume.

Create the admin

Open http://<your-host>:3040. A short setup wizard creates the admin account and offers any OctoPrint servers it found in Docker or over mDNS.

Add your printer

Discover & approve

  1. Open Settings → Printers & Discover and pick the printer from Docker, Arcane or the network.
  2. Add → Approve in OctoPrint, sign in there and click Allow.
  3. octo·modern picks up the key, tests it and saves the printer.

URL + Application Key

  1. The URL as the server reaches it, e.g. http://octopi.lan or http://host.docker.internal:5000.
  2. A key from OctoPrint's Settings → Application Keys.
  3. Test connection shows the version and any missing permission.

More in the docs: reverse proxies, self-signed certificates and Docker networking.

Security

Your printers, not the whole internet's

octo·modern sits between the browser and OctoPrint, so the things that matter never leave the server.

Keys sealed at rest

AES-256-GCM, bound to each printer, never sent to a browser, not even an admin's. Store and key file are mode 0600.

The browser never talks to OctoPrint

Status, push updates, webcam streams, thumbnails and uploads all go through octo·modern. Camera URLs stay server-side too.

Checked on the server

Roles and printer access are enforced on every route. Dangerous actions answer 409 until the request confirms.

Read-only where it can be

Discovery only reads Docker (through a socket proxy) and Arcane. Status tokens are hashed, GET-only and never become sessions.

FAQ

Questions

Why doesn't Discover find my OctoPi over mDNS?

Multicast only reaches one network segment, and inside Docker's default bridge network nothing answers. Run octo·modern with network_mode: host or on a macvlan/ipvlan network to use mDNS.

On a bridge network, use Discover's subnet scan instead (e.g. 192.168.4.0/24); it fingerprints OctoPrint without a key.

My camera is on a LAN address. Will the webcam work remotely?

Yes, for MJPEG cameras (mjpg-streamer, ustreamer, camera-streamer): octo·modern relays the stream, so it works wherever octo·modern does. The relay closes the camera connection when the last viewer leaves.

HLS and WebRTC streams can't be relayed as an image; you get a snapshot and an Open stream link the browser must be able to reach.

Does my browser ever see the OctoPrint API key?

No. Keys are stored encrypted on the server and every request to OctoPrint, including the push connection, webcam images and uploads, goes through octo·modern. With the Application Keys flow, the key goes from OctoPrint straight to octo·modern's server.

Can people watch printers without an account?

Yes. Under Settings → Sign-in, make sign-in optional: visitors become guests who can either watch or control printers, while admin pages still need an admin account.

OCM_AUTH=disabled goes further and gives everyone full access; only use it on a trusted network.

Does it replace OctoPrint?

No. Each printer keeps running OctoPrint; octo·modern is a front end that talks to its API. Nothing gets installed on the Pi, and OctoPrint's own UI keeps working.

Can it run behind a reverse proxy?

Yes. Behind TLS, set PROTOCOL_HEADER=x-forwarded-proto and HOST_HEADER=x-forwarded-host so secure cookies and SSO callbacks work, and raise the proxy's upload limit (nginx: client_max_body_size) for big G-code files.
