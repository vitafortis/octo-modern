Adding a printer

You need two things from each OctoPrint.

  • Its URL, as octo·modern's server reaches it. Usually http://<pi-ip> or http://octopi.lan. Behind a reverse proxy at a path, include the path (https://print.example.com/octoprint). Inside Docker, localhost is octo·modern's own container: use the host's IP, or host.docker.internal for an OctoPrint on the same Docker host. .local (mDNS) names usually don't resolve inside containers.
  • An API key. In OctoPrint, open Settings → Application Keys and generate one named "octo·modern", or copy a user's key from User Settings → API key. The key acts with the permissions of the OctoPrint user it belongs to.

Test connection shows OctoPrint's version, which user the key belongs to, and any permission the key lacks. Self-signed certificate on your LAN? Turn off Verify TLS certificate for that server.

Or let octo·modern find it: the setup wizard lists OctoPrint servers it finds in Docker and over mDNS right after you create the admin, and Discover does the rest. You approve the key in OctoPrint instead of copying it.

Discover

Discover (admins) finds OctoPrint servers and adds them in two clicks. It looks in three places:

  • Docker: every container on each Docker endpoint, recognized by image or by port plus OctoPrint markers. Each candidate shows its image, compose project and the serial devices mapped into it, so you can tell which printer it drives.
  • Arcane: the same, for every environment an Arcane instance manages, through its API with a read-only key (environments:list, containers:list, containers:read).
  • Network: mDNS (_octoprint._tcp) and a subnet scan for OctoPi and anything else outside Docker.

Add asks OctoPrint for an Application Key: Approve in OctoPrint opens OctoPrint's approval page; sign in as the user whose permissions the key should have and click Allow. octo·modern picks the key up, tests it and saves the printer. OctoPrint allows 3 key requests a minute and drops requests nobody approves within 10 minutes.

Docker, through a read-only socket proxy

octo·modern only lists and inspects containers, so don't give it the raw socket. Run docker-socket-proxy next to it with CONTAINERS=1 and POST=0:

compose.yaml
services:
  octo-modern:
    environment:
      OCM_DOCKER_HOSTS: tcp://docker-proxy:2375
    depends_on: [docker-proxy]
  docker-proxy:
    image: tecnativa/docker-socket-proxy:latest
    restart: unless-stopped
    environment:
      CONTAINERS: 1
      POST: 0
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro

More Docker hosts? Run a proxy on each and list them all: OCM_DOCKER_HOSTS=tcp://docker-proxy:2375,tcp://nas.lan:2375.

mDNS needs the LAN

Multicast only reaches one network segment: inside Docker's default bridge network, nothing answers. Run octo·modern with network_mode: host, or attach it to a macvlan/ipvlan network on your LAN. On a bridge network, use the subnet scan instead.

Subnet scan

Enter a CIDR (192.168.4.0/24), a range (192.168.4.20-40) or addresses, and ports (default 80, 5000, 443). Scans are limited to 4096 addresses, need an admin and are recorded in the audit log.

Guests and single sign-on

Under Settings → Sign-in you can make sign-in optional: visitors use it as guests who can either watch or control printers, while admin pages still need an admin account. Single sign-on works with any OIDC provider (Authentik, Authelia, Keycloak, Pocket ID, Google, …); register <your-url>/auth/oidc/callback as the redirect URI.

Print queue

Queue in the sidebar holds prints waiting for a printer; each printer's Queue tab shows what it could take. Add jobs from the library, a printer's files (they print on that printer) or an upload, or let a slicer add them.

  • Which printer: one printer, or any compatible printer, meaning one whose tags include all the job's tags. Admins tag printers on the Queue page (0.4mm, petg, bed:300, …).
  • Order and copies: drag jobs, or use the up/down arrows (the ⋯ menu on phones). Copies print one after another.
  • Bed is clear: after every print the printer waits until someone confirms its bed is clear, on the overview card, the printer page or the Queue page, or with POST /api/status/<id>/bed-clear and a token allowed to. Notification rules with Bed clear needed send a queue.bed_clear_needed notification.
  • Failures: a failed or cancelled queued print marks the job failed (requeue it with one click) and pauses that printer's queue. Pause queue stops all new starts.

Files are transferred when the printer doesn't already have them, then printed; each run links to its print history entry. Everything is stored, so restarts pick up where they left off.

Slicer uploads

octo·modern speaks enough of OctoPrint's API (/api/version, /api/server, /api/files/local uploads) for slicers to upload to it. It lives under /octoprint, apart from octo·modern's own /api, so the address to enter is:

slicer host
http://octo-modern.lan:3040/octoprint

Create a key under Integrations → Slicer upload keys and choose where its uploads go: the print queue (a printer, or any printer with given tags), a folder in a writable library source, or one printer (optionally allowed to start the print). The key is an ocm_… token that opens /octoprint/api/… only.

  • PrusaSlicer: Physical printer → Host type OctoPrint, URL as above, API key = the key → Test.
  • OrcaSlicer: printer Connection → Host type Octo/Klipper, URL as above, API key = the key → Test.
  • Cura: install OctoPrint Connection from the Marketplace → Preferences → Printers → Connect OctoPrint → Add: host octo-modern.lan, port 3040, path /octoprint/, then paste the key (without ocm_ if Cura refuses the underscore).

Status API for dashboards

Create a token under Integrations → Status API tokens (admins). It's shown once; only its SHA-256 is stored. Tokens open these routes only, and only for GET.

RouteReturns
GET /api/status{ printers, online, printing, checkedAt, items: [...] }
GET /api/status/<id>One item; add ?strict=1 to get HTTP 503 while it's unreachable or in an error state
GET /api/status/badge/<id>.svgA shields-style badge, e.g. printing 42%
POST /api/status/<id>/bed-clearConfirms the bed is clear for the print queue; only tokens created with May confirm bed clear

Send the token as Authorization: Bearer ocm_…. Widgets that can't set headers can use ?token=ocm_…; give such a widget its own token.

shell
curl -H "Authorization: Bearer $OCM_TOKEN" http://octo-modern.lan:3040/api/status

Smart plugs

Admins set up a printer's plug from its settings (the settings icon in the printer header → Smart plug); the dashboard shows a Power card once a plug exists. Test reads its state without switching it. Passwords and tokens are sealed like API keys and never sent back to the browser.

  • Shelly Gen1 (/relay/<n>, Basic login) and Gen2+ (RPC Switch.Set/Switch.GetStatus, Digest login), with watts and energy.
  • Tasmota (/cm?cmnd=Power<n> On, optional web admin password), energy from Status 8.
  • Home Assistant: a switch, light or input_boolean entity with a long-lived token, plus optional power and energy sensors.
  • HTTP: your own on, off and status requests; the status answer is matched against a text or /regex/.

Operators switch printers from the printer header, the Power card, the overview card or the sidebar's right-click menu. Turning off disconnects OctoPrint first; it asks while the hotend or bed is hot, and always twice while a print runs (the server insists). After power-on octo·modern connects the printer, retrying for about three minutes. Power off after a print waits until the printer has been idle N minutes (default 10) and the hotend is below X °C (default 50); a new print or Keep on cancels it. Power on for new prints switches an off printer on when a file is sent to print, or when the print queue has a job for it and its bed is confirmed clear; a due power-off waits while queued jobs need the bed cleared. Everything is audited (power.*), and notification channels can subscribe to power on/off.

Webcams and files

octo·modern reads each printer's cameras from OctoPrint's webcam settings: the classic webcam and any camera a webcam plugin adds. To use a different camera, put its stream or snapshot URL in the server's Webcam field.

  • MJPEG streams are relayed through octo·modern, with snapshots for the overview cards. The relay closes the camera connection as soon as the last viewer leaves; streams pause while the page is hidden.
  • HLS and WebRTC streams get a snapshot (if there is one) and an Open stream link, which the browser must be able to reach.

Uploads go to OctoPrint's local storage and are streamed as they arrive, so memory use doesn't grow with the file; the image allows up to 4 GB (BODY_SIZE_LIMIT). A reverse proxy in front may have its own limit (nginx: client_max_body_size).

Notifications

Admins set them up under Notifications. Secrets (tokens, webhook URLs, passwords) are stored encrypted and never sent back to the browser; Send test tries the settings on screen and shows the service's answer word for word when it fails.

  • Channels: ntfy, Discord, Slack (incoming webhook, Block Kit), Telegram (bot token and chat ID, the snapshot as a photo), Pushover, Gotify, Matrix (homeserver, room ID, access token), email over SMTP (STARTTLS or TLS, snapshot inline), Home Assistant (webhook trigger and/or a notify.* service) and generic JSON webhooks.
  • Events: print started, progress milestones (percentages, minutes left), paused (filament runout, M600, a pause in the G-code, or who), finished, failed, cancelled (and by whom), printer offline, error, back, still hot after a print; plus queue.bed_clear_needed, failure.suspected, spool.low, maintenance.due and power.off from other features.
  • Messages: printer, file, elapsed and estimated time, filament, who started it, a link back (set the public URL, or ORIGIN) and the webcam snapshot. Slack, Gotify and Home Assistant show pictures only by link: turn on Share snapshots by link (unguessable links, 48 hours).
  • Rules, quiet hours, limits: rules pick printers × events → channels; quiet hours per channel can still let errors through; the same event goes to a channel once per 10 minutes and at most 20 messages per 10 minutes, so flapping printers stay quiet. Recent deliveries shows the last 100 with their status.

Other server code sends its own with notify({ kind, printerId, title, message, fields }); webhooks get a JSON document (version 2) with event, severity, title, message, printer, print, fields, data, url and optionally the image.

Failure detection

octo·modern watches printing printers with Obico's failure-detection model (the "Spaghetti Detective"), in your own ml_api container from obico-server; no Obico account or cloud. Add it with compose.detect.yaml from the repository:

echo "ML_API_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose -f compose.yaml -f compose.detect.yaml up -d

Check Settings → Failure detection (ML API URL, token, and octo·modern's address as the container sees it, usually http://octo-modern:3000), press Test for a full round trip, then turn detection on in a printer's Failure detection tab.

  • Frames: after the first minutes of a print (default 5), a webcam snapshot every 10 s goes to GET /p/?img=<url>; the container downloads it and answers boxes and confidences. That's the ML API's only interface: it takes no image bytes, so octo·modern serves each frame through a single-use, 30-second link.
  • Score: Obico's own algorithm: the frame's confidences summed, smoothed over 12 frames, minus a long-term baseline per printer, times the sensitivity. Warning from 33 %, failure from 67 % on Obico's 0–100 % scale.
  • Actions: a warning sends a failure.suspected notification with the annotated frame (to the channels of every notification rule with Failure suspected). A failure does nothing, notifies, or pauses the print, audited as octo·modern detector. This is a false alarm turns it off until the print ends.

Spools, costs and maintenance

The Filament page shows which Spoolman spool is on which printer and holds the admin settings; each printer's dashboard has a Filament card with the active spool per extruder.

  • Connecting (admins): Spoolman's address, e.g. http://spoolman.lan:7912, and optionally an auth header for a reverse proxy in front of it (stored encrypted, never sent back to the browser). Only the server talks to Spoolman.
  • Choosing a spool (operators): search Spoolman's spools by name, vendor, material or location, with the colour and what's left. One spool per extruder; a spool sits on one tool at a time.
  • Reporting use: while printing, about every metre, and the rest when the print ends (PUT /api/v1/spool/<id>/use with use_length), so Spoolman's total matches the history. Failed reports are retried for a week and never sent twice.
  • Before printing: when the file needs more than the spool has, starting it asks first (the API answers 409 with confirmRequired). An unreachable Spoolman never holds a print up.
  • Low spools turn red below the threshold (100 g by default) and send a spool.low notification once.

Cost per print (admins set the prices): filament by weight, at the spool's price from Spoolman or a price per kg per material, plus electricity (print time × the printer's power draw × the price per kWh). It's on every history entry, in the History stats per printer and in the CSV export (filament_g, material, cost_filament, cost_energy, cost_total); earlier prints are costed too, and Recalculate history applies new prices.

Maintenance: per-printer tasks every so many print hours, kg of filament or days, counted from the print history since they were last done. Nozzle change, belt tension, lubrication, bed cleaning and e-steps are offered. Tasks are due soon at 90 % and overdue past their interval; the sidebar counts overdue ones and maintenance.due is sent once. Done logs who, when and your notes, and restarts the count.

Stats

The Stats page sums up the print history over the last 30 days, 90 days, 12 months or all time, for every printer or one.

  • Tiles: print hours, finished prints, success rate, filament in metres and grams, cost (only when prints have one) and the average print.
  • Charts: print hours per day, week or month stacked by printer, and successes, failures and cancels over the same buckets. Hover or tap a column for its numbers; screen readers get them as a table.
  • Tables: most-printed files (each opens the History filtered to it), why prints failed or were cancelled, and utilisation, the share of the range each printer spent printing.
  • Filament per material, and per Spoolman spool when Spoolman is set up.
  • Export CSV: the prints of the range, with the History export's columns.

Everyone sees only the printers they have access to. Buckets follow the browser's time zone (sent as tz), so months and days match your calendar across daylight-saving changes; without one, the server's TZ is used. The API is GET /api/stats?range=30d|90d|12m|all&printer=<id>&tz=<zone>.

G-code preview

The Preview tab on a printer shows the job's toolpath; the cube button next to a file in Files or the Library previews any other. Drag to orbit (right-drag or Shift to pan), scroll or pinch to zoom, double-tap to reset; the slider and ↑/↓ change the layer. Layer shows one layer from above; Travel adds moves without extrusion; the legend hides feature types.

  • Live: during a print, the preview follows OctoPrint's position in the file: the layer being printed, what's done and what's left, and the nozzle.
  • Understood: G0/G1, G2/G3 arcs, G90/G91, M82/M83, G92, G20/G21. Layers from slicer comments (;LAYER_CHANGE, ;LAYER:n) or from Z; colours from ;TYPE:/;FEATURE: (PrusaSlicer, OrcaSlicer, Bambu Studio, Cura). Not .bgcode or SD card files.
  • Big files stream in 16 MB ranges and are parsed in a Web Worker as they arrive; memory is capped (3 million moves on computers, 1.5 million on phones) by merging short segments, and drawing is capped per frame.
  • Files are fetched by the server with the printer's key or the source's credentials; anyone who can see the printer or source can preview, viewers included.

Camera wall

Cameras shows every camera you may see, one column on a phone and as many as fit on wider screens, with state, progress and temperatures on each. Tap one for full screen.

  • Auto streams live up to four cameras and refreshes snapshots for more (browsers allow six connections per host, and a wall of streams is a lot of bandwidth). Cameras pause when scrolled away, when the tab is hidden and while one is open full screen.
  • Kiosk hides everything else, hides the cursor, keeps the screen awake and can rotate through the cameras.
  • Options are in the URL, e.g. /cameras?kiosk=1&layout=3&mode=snapshot&every=5&rotate=20, so a wall tablet can open a bookmark.

Security model

  • API keys are sealed with AES-256-GCM, bound to their printer's id, and never sent to the browser, not even to admins. The SQLite file and key file are created with mode 0600. Back up secret.key, or set OCM_SECRET_KEY; without it, stored keys can't be recovered.
  • The browser never talks to OctoPrint. Status, the push connection, webcam images and streams, thumbnails and uploads all go through octo·modern. Camera URLs of relayed cameras aren't sent to the browser either.
  • Least privilege: an OctoPrint Application Key acts as the user who approved it. Use a key of a user with only the permissions you want octo·modern to have; Test connection lists what it lacks.
  • Access is checked on the server for every printer-scoped page and API call. Confirmations for dangerous actions are enforced by the server.
  • API tokens (ocm_ + 32 random bytes, SHA-256 hashed at rest) only work on GET /api/status…; they never become sessions, and repeated bad tokens from one address are throttled.
  • Sign-in is by OIDC or local accounts (scrypt-hashed passwords, login throttle). Sessions are httpOnly cookies that end when the user is disabled or their role changes. Writes from another origin are rejected.
  • Discovery is admin-only and read-only: Docker and Arcane are only read, a socket proxy keeps writes blocked, and subnet scans are capped at 4096 addresses and audited.
  • Failure detection frames are served at /api/detect/frame/<token>: a random 256-bit, single-use token, valid 30 s, for one captured frame (never the camera). It's the only path besides the status API that works without a session, and only for GET.
  • Backup files hold decrypted API keys and the SSO client secret, re-encrypted with AES-256-GCM under a key derived from your passphrase (scrypt). Treat them like a password manager export.

Backup & restore

Under Settings → Backup & restore, admins download an encrypted file with printers (and their API keys), users, settings (including failure detection), notification channels and rules, the print queue (not files uploaded to it), Spoolman, costs and maintenance and, when ticked, the print history with or without its pictures. It's sealed with a passphrase you choose, not the master key, so it restores on a new install. A restore shows what it will add or update before applying; history entries and queued jobs already present are kept, nothing is deleted. The audit log and API tokens aren't included.
